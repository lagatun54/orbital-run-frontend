# Орбитальный сбор — клиент

Браузерная игра на PixiJS. Клиент собирается и публикуется независимо от
Go-бэкенда; для онлайн-матчей и общего рейтинга ему нужен адрес API.

## Локальный запуск

Через Docker Desktop или Docker с Compose 2.32 и новее, из папки фронтенда:

```sh
docker compose up --build --watch
```

Откройте http://localhost:5173. Compose передаёт изменения исходников в
контейнер, а Vite обновляет страницу. Изменения в `package-lock.json`
пересобирают образ. Если на порту 5173 уже запущен `npm run dev`, сначала
остановите его.

### Запуск через Node.js

В папке фронтенда с Node.js 22.12 или новее выполните:

```sh
npm ci
npm run dev
```

Откройте http://localhost:5173. Vite автоматически обновляет страницу после
изменений. По умолчанию доступна локальная игра с ботом.

Для онлайн-матчей запустите Go-бэкенд в его отдельном репозитории:

```sh
FRONTEND_ORIGIN=http://localhost:5173 docker compose up -d --build --wait
```

В папке фронтенда скопируйте `.env.example` в `.env.local` и заново запустите
выбранную команду фронтенда. `VITE_BACKEND_URL` в этом файле указывает на
`http://localhost:8080`. Браузер загружает рейтинг и отправляет результаты
по gRPC-Web, а кадры матча получает через WebSocket на `/ws`. Используйте
origin без пути и параметров.

## Код клиента

Клиент написан на TypeScript. `npm run typecheck` проверяет типы без сборки;
`npm run build` компилирует модули и останавливается при ошибках типов.
Результат лежит в `dist`. Для проверки сборки локально используйте `npm run preview`.

- `assets/` — исходные PNG арены и интерфейса. При запуске `npm run dev` и
  `npm run build` AssetPack собирает два атласа KTX2. Скрипт упаковывает их
  разметку, текстуры и транскодер PixiJS в `.generated/game.pack`. Vite
  публикует пакет под именем `dist/assets/game-<хеш>.pack`. Чтобы пересобрать
  пакет отдельно, выполните `npm run assets`.
- `src/app/` — точка входа и настройка API.
- `src/game/arena/` — состояние арены и PixiJS-рендер.
- `src/game/round/` — ход раунда, локальная симуляция и WebSocket-сессия.
- `src/game/ui/` — HTML-меню, табло, мобильный джойстик и таблица лидеров поверх холста.
- `src/leaderboard/` — таблица рекордов и отправка сохранённых результатов.
- `src/gen/scores/v1/` — TypeScript-схемы из Protobuf-контрактов бэкенда.
- `src/shared/` — проверка внешних данных.
- `src/vendor/` — внешний код и его объявления типов.
- `index.html` и `style.css` — точка загрузки и стили холста, `scripts/` — обновление движка.

TypeScript-контракты лежат в папках `interfaces/` рядом с модулями, которым
они принадлежат. События раунда описаны в `src/game/round/interfaces/events.ts`.

Контроллер раунда принимает команды `start` и `direction`, получает события
от текущей сессии и публикует `starting`, `phase-changed`, `interrupted` и
`finished`. Точка входа передаёт эти события интерфейсу и рейтингу. Кадры
передаются напрямую рендеру арены и табло. Список
лидеров закреплён поверх правого верхнего угла арены. Без API он
показывает рекорды с этого устройства. Enter запускает раунд, R раскрывает
список, если в нём больше десяти записей, Esc сворачивает его. Управлять
кораблём можно джойстиком, WASD или стрелками. Имя пилота
необязательно; поле на холсте принимает ввод с физической клавиатуры.

## Состояние приложения

Zustand хранит фазу, режим и итог раунда. Подписчики получают обновления при
переходах между фазами. В режиме разработки `window.orbitalRunState` возвращает
снимок с последним кадром, а `window.orbitalRunStore.getState()` возвращает
состояние Zustand. Чтобы увидеть переходы, выполните в консоли браузера:

```js
const unsubscribe = window.orbitalRunStore.subscribe(
  state => state.phase,
  (phase, previous) => console.log(previous, '→', phase),
)
// Чтобы отключить наблюдение, вызовите unsubscribe().
```

| Фаза | Что происходит |
| --- | --- |
| `loading` | Арена загружается. |
| `error` | Не удалось запустить приложение. Причина доступна в `error`. |
| `ready` | Можно начать раунд в режиме `online` или `local`. После обрыва связи доступен `local` с `reason: 'disconnected'`. |
| `connecting` | Клиент ждёт первый кадр онлайн-матча. При обрыве связи до первого кадра запускается локальный раунд. |
| `starting` | Запускается локальный раунд. |
| `countdown` | Идёт отсчёт до старта. |
| `playing` | Идёт раунд. |
| `finished` | Раунд завершён, итог доступен в `result`. |

В фазах `countdown`, `playing` и `finished` в `frame` доступны таймер, очки
и позиции объектов на арене.

## Движок арены

Арена использует `initEngineApplication` и `createSceneView` из
[Scene Engine](https://github.com/lagatun54/engine-pixi-js). В
`src/vendor/scene-engine.mjs` лежит собранный срез этих двух модулей;
его заголовок фиксирует исходный коммит. Он использует тот же PixiJS,
что и игра. Для обычной сборки не нужен доступ к репозиторию движка.

`src/game/arena/scene.ts` описывает слои арены и рисует состояние матча.
Сетевой обмен, управление, локальная симуляция и таблица рекордов
остаются в коде игры. Spine, ECS, tween и реактивные модули в срез не входят.

Для обновления выберите коммит в отдельной чистой копии движка и выполните
из корня игры (нужен `esbuild` 0.25.12 в PATH):

```sh
sh scripts/vendor-scene-engine.sh /path/to/engine-pixi-js
npm run build
```

## Публикация в GitHub Pages

В Settings → Pages выберите GitHub Actions. Workflow Frontend собирает и
публикует сайт из основной ветки. Его также можно запустить вручную.

При публикации клиент использует API по адресу
`https://orbital-run-api.onrender.com`. Чтобы сменить API, задайте
`BACKEND_URL` в Settings → Secrets and variables → Actions → Variables и
запустите workflow заново. Адрес должен использовать HTTPS.

На бэкенде установите `FRONTEND_ORIGIN=https://lagatun54.github.io`.
Для собственного домена укажите его origin без пути. Клиент обращается
к `/ws` по WebSocket и к `LeaderboardService` и `ResultsService` по gRPC-Web.
